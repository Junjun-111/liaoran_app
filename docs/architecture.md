# 「了然」App 架构与阶段计划

## 项目定位

单机个人资产管理 App（Flutter / Android）。核心参考「有数」的业务逻辑：
日均成本计算、资产状态流转、闲置盈亏复盘、资产总览看板，并内置完整的订阅管理。

## 已确认的设计决策（2026-08-18）

1. **本地存储**：现阶段**不引入数据库**，数据暂存内存（沿用 `SubscriptionStore` 模式）。
   后续用户明确需要持久化时，再接入 Hive（预留仓储接口，UI 层不感知）。
2. **图表**：不使用第三方图表库，采用**自绘智慧环形图**（CustomPainter），
   配色沿用现有薄荷绿渐变 + 光斑蓝/粉，视觉与整体风格一致。
3. **语言**：本期仅简体中文，不做国际化框架。
4. **订阅状态规则**：只做自动判定——到期日/下次扣款日已过 → 自动变为「已过期」；
   未过期 → 「生效中」。不做额外复杂优化。
5. **个人中心**：现有功能全部实现（货币单位、小数点设置、坚果云同步（本地备份还原）、
   分类管理、标签管理、功能视图样式、应用锁定）。

## 分层结构（目标形态，渐进迁移）

```
lib/
  core/           主题令牌、通用组件、响应式工具、错误定义
  domain/         纯 Dart：模型、枚举、计算引擎（日均成本/盈亏）、仓储接口、用例
  data/           Hive 数据源、适配器、仓储实现、备份导入导出（待数据库接入后落地）
  state/          全局内存 Store（ChangeNotifier）
  pages/          页面（含页面私有组件）
  widgets/        跨页面共享组件
  models/         领域模型
  services/       原生通道等服务
```

迁移原则：**渐进式**。现有 `lib/pages`、`lib/theme` 不强行搬移，
在各阶段改造对应模块时再归位，避免大范围改动破坏现有视觉。

## 分层纪律

- `domain/` 只放可单测的纯逻辑（无 Flutter 依赖），计算引擎全部在此。
- 页面只通过 Store/ViewModel 取数据、调用例，不直接写业务判断。
- UI 层禁止出现「金额计算、状态判定、日期推算」等业务逻辑。
- 共享样式一律取自 `AppColors` / `AppTextStyles`，禁止页面内硬编码新色值。

## 阶段计划（每阶段完成 → 用户验收 → 继续）

0. 基建：分层规范文档、共享组件抽取、内存设置服务
1. 存储与设置服务：分类/标签字典、设置接口预留
2. 日均成本计算引擎 + 边界单测
3. 资产模块：表单落地、列表/详情、状态流转、卖出记录
4. 订阅管理完善：状态自动判定、汇总、筛选、编辑
5. 首页看板：自绘智慧环形图 + 真实数据
6. 心愿清单：增删改查 + 攒钱进度
7. 个人中心功能完善 + 打磨（无障碍、性能、备份还原、上架检查）

## 验收门槛（每阶段）

- `flutter analyze` 0 错误
- 现有测试全绿
- Debug APK 构建成功并安装到真机
- 视觉与交互无回归
